Software uit de repository

Op Windows haal je een programma op bij de maker, in de vorm van een setup.exe die je zelf uitvoert. Ubuntu werkt omgekeerd: de programma's staan op een centrale server, en je machine haalt ze daar zelf op zodra je zegt welk je wil. Die server heet een repository, en zolang je software eruit komt, blijft ze bijgewerkt zonder dat je er iets voor doet.

Wat een repository is

Een repository is een opslagplaats met duizenden kant-en-klare pakketten, beheerd door de mensen achter de distributie. Zet iemand er een nieuwe versie van een programma in, dan wordt die beschikbaar voor iedereen die op die repository aangesloten is. Je machine kent de adressen van de repositories waar ze op aangesloten is, en houdt daarvan een lijst bij van wat er te krijgen is en in welke versie.

Wat in de repository van Ubuntu staat, is nagekeken en op elkaar afgestemd, en dat heeft een prijs: het is meestal niet de allernieuwste versie. Dat is de afweging die je bij elke weg in dit labo terugziet, stabiliteit tegenover versheid.

Dependencies

Bijna geen programma staat op zichzelf. Het gebruikt bibliotheken die andere programma's ook gebruiken: code om een venster te tekenen, om een netwerkverbinding op te zetten, om een afbeelding te lezen. Die andere pakketten heten de dependencies van een programma.

Het stuk software dat de pakketten van een repository beheert, heet een package manager, en zijn belangrijkste taak is precies die: uitzoeken wat een pakket nog nodig heeft en dat er meteen bijhalen. Vraag je één programma, dan installeert hij er stilzwijgend vijf, en bij een update werkt hij ze alle vijf bij.

Software Center

Het Ubuntu Software Center is de winkel met vensters: je zoekt op naam, je klikt op Install, en de rest gebeurt vanzelf. Achter dat venster zit dezelfde repository als achter de commando's hieronder, dus wat je hier installeert, wordt ook automatisch bijgewerkt.

Niet alles staat erin. Grote leveranciers zetten hun software in de repository van Ubuntu, kleine vaak niet, en dan heb je een van de wegen van de volgende pagina nodig.

apt

apt is de package manager van Debian, en dus ook van Ubuntu. De naam staat voor Advanced Packaging Tool. Je gebruikt hem met twee commando's.

elm@elm-VirtualBox:~$ sudo apt update
elm@elm-VirtualBox:~$ sudo apt install ssh

update haalt de lijst op van wat er in de repositories te krijgen is; het installeert nog niets. install haalt daarna het pakket zelf, en je ziet in de uitvoer meteen wat een dependency doet: je vroeg ssh en er komen er vijf.

De hoofdletter in [Y/n] is het standaardantwoord

Bij Do you want to continue? hoef je alleen op ENTER te drukken. De Y staat in hoofdletters en dat is wat er gebeurt als je niets typt. Wil je toch antwoorden, dan typ je y gevolgd door ENTER.

snap

Een snap is een pakket dat alles wat het nodig heeft zelf meebrengt, in plaats van het bij dependencies op je machine te zoeken. Het is daarom groter, en het staat los van de versie van je distributie: waar een pakket uit de gewone repository vaak pas bij een nieuwe Ubuntu vernieuwt, komt een snap bij zodra de maker een nieuwe versie uitbrengt.

De makers van VLC raden hun snap om precies die reden aan. Het commando lijkt op dat van apt.

elm@elm-VirtualBox:~$ sudo snap install vlc

Een repository van de leverancier

Staat een programma in geen van de drie, dan heeft de leverancier soms een eigen repository. Je zet het adres ervan bij de adressen die je machine al kent, en vanaf dan gedraagt zijn software zich als alle andere: apt vindt ze en houdt ze bij.

De adressen die je machine kent, staan als tekstbestanden onder /etc/apt/sources.list.d/, één bestand per repository. Zo'n regel heet een APT-regel en ziet er zo uit:

deb [signed-by=/etc/apt/keyrings/spotify.gpg] http://repository.spotify.com stable non-free

Het woord deb zegt dat het om kant-en-klare pakketten gaat, tussen de haken staat de sleutel, daarna komt de server, dan de tak die je volgt, en tot slot de afdeling waarin het pakket zit.

Waarom er een sleutel bij hoort

Elk pakket in een repository is digitaal ondertekend, en je machine controleert die handtekening voor ze iets installeert. Zo weet ze dat het pakket van de leverancier komt en onderweg niet gewijzigd is. De handtekeningen van Ubuntu staan er van bij de installatie in; die van een repository die je zelf toevoegt niet, dus die haal je op bij de leverancier en zet je erbij.

Zo'n sleutel komt in een eigen bestand onder /etc/apt/keyrings/, en het stuk signed-by in de APT-regel bindt haar aan die ene repository. Daardoor mag de sleutel van Spotify alleen de pakketten van Spotify ondertekenen. Er bestond vroeger een commando apt-key dat elke sleutel op één hoop zette, waardoor elke repository voor elke andere kon tekenen; Ubuntu heeft dat afgevoerd, en je komt het nog tegen op bladzijden van leveranciers die hun instructies niet bijgewerkt hebben.

Ontbreekt de sleutel, dan weigert apt update die repository, met een melding waarin het woord signed valt. Het is geen netwerkfout en niet iets wat je met opnieuw proberen oplost.

Je systeem up to date houden

Bijwerken doe je met twee commando's, of met de Software Updater die af en toe uit zichzelf verschijnt. sudo apt update haalt eerst de lijst op, en sudo apt upgrade installeert daarna van elk pakket de nieuwere versie.

Dat werkt alleen voor wat je uit een repository gehaald hebt. Software die je op een andere manier geïnstalleerd hebt, staat in geen enkele lijst en wordt dus ook niet bijgewerkt. Dat is de reden waarom de volgorde van dit labo de volgorde is waarin je de vijf wegen probeert.
