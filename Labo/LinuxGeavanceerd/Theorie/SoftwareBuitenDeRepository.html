Software buiten de repository

Staat een programma in geen enkele repository, dan haal je het rechtstreeks bij de maker. Er zijn daar drie vormen voor, en ze liggen op een rij: bij elke stap doet de leverancier minder werk voor je en jij meer. Bij alle drie geldt hetzelfde: wat je zo installeert, staat in geen enkele pakkettenlijst en wordt dus door apt upgrade niet bijgewerkt.

Een .deb bestand

Een .deb is een kant-en-klaar pakket dat je zelf downloadt, de tegenhanger van een setup.exe op Windows. Het bevat de bestanden van het programma en een beschrijving van waar ze horen te staan, en je installeert het met dpkg.

elm@elm-VirtualBox:~/Downloads$ sudo dpkg -i google-chrome-stable_current_amd64.deb

dpkg is de laag onder apt: hij pakt één pakket uit en zet het op zijn plaats. Wat hij niet doet, is dependencies gaan halen. Ontbreekt er een bibliotheek, dan installeert hij het pakket half en stopt hij met een foutmelding.

dpkg: dependency problems prevent configuration of google-chrome-stable:
 google-chrome-stable depends on libappindicator1; however:
  Package libappindicator1 is not installed.
dpkg: error processing package google-chrome-stable (--install):
 dependency problems - leaving unconfigured

Dat repareer je met apt, die wél weet waar bibliotheken vandaan komen. De optie -f staat voor fix broken: zoek uit wat er halfweg blijven steken is, haal wat ontbreekt en maak de installatie af.

elm@elm-VirtualBox:~/Downloads$ sudo apt-get install -f

Een installer script

Soms krijg je geen pakket maar een archief met daarin de bestanden en een script dat ze op hun plaats zet, meestal install.sh. Dat script is een tekstbestand met commando's erin, en je voert het uit als een programma.

Een archief pak je uit met tar. De extensie zegt hoe het ingepakt is en dus welke optie je nodig hebt.

Twee soorten archief, en hoe je ze uitpakt
Bestand Commando Wat de letters doen
.tar.gz tar xvzf archief.tar.gz x uitpakken, v toon elke naam, z gecomprimeerd met gzip, f uit dit bestand
.tar.xz tar -xf archief.tar.xz Zonder z: tar herkent zelf dat het xz is

Aan welk bestand in zo'n map het installer script is, zie je aan zijn naam en aan zijn rechten: de drie x-en in -rwxr-xr-x zeggen dat het uitgevoerd mag worden.

-rwxr-xr-x  1 elm  elm  5,8K Feb 13 10:32 arduino-linux-setup.sh
drwxr-xr-x 13 elm  elm  4,0K Feb 13 10:32 examples
-rwxr-xr-x  1 elm  elm   11K Feb 13 10:32 install.sh
drwxr-xr-x  6 elm  elm  4,0K Feb 11 13:00 java

Je start het met sudo ./install.sh. De ./ ervoor zegt dat het script in de map staat waar je nu bent, en sudo staat erbij omdat een installatie bestanden en instellingen wegschrijft buiten je eigen map, waar een gewone gebruiker niet mag schrijven.

Een script uitvoeren is een programma van iemand anders vertrouwen

Wat er in install.sh staat, gebeurt met de rechten van root zodra je er sudo voor zet. Haal zo'n script dus alleen bij de maker zelf, en niet uit een zoekresultaat.

Broncode compileren

De laatste weg is de langste: de maker levert alleen de broncode, en jij maakt er zelf een uitvoerbaar programma van. Je hebt daar een compiler voor nodig, en een programma dat weet in welke volgorde de stukken vertaald en samengevoegd moeten worden. Dat tweede is make.

make is dus zelf geen compiler: het leest een bestand met de naam Makefile dat in de broncode zit, en roept op basis daarvan de compiler aan, op Linux meestal gcc.

elm@elm-VirtualBox:~/Downloads/noip-2.1.9-1$ sudo make 
gcc -Wall -g -Dlinux -DPREFIX=\"/usr/local\" noip2.c -o noip2
noip2.c: In function 'dynamic_update':
noip2.c:1595:6: warning: variable 'i' set but not used [-Wunused-but-set-variable]
   int i, x, is_group, retval, response;

Een warning is geen error. Een warning zegt dat de compiler iets vreemds ziet en toch doorgaat; een error zegt dat hij het niet vertaald krijgt en stopt. Zolang er alleen warnings staan, is je programma gemaakt.

Daarna zet sudo make install het resultaat op zijn plaats, meestal onder /usr/local/bin. Waar dat precies is en hoe je het programma start, staat in het tekstbestand dat bij de broncode zit, dikwijls README of README.FIRST genaamd.

Weg Dependencies Blijft bijgewerkt Wanneer je ze neemt
