Docker

De vijf wegen van de vorige pagina's zetten een programma tussen de andere programma's op je machine, met de bibliotheken die het nodig heeft ernaast. Een container doet het anders: hij zet het programma en alles wat het nodig heeft in een afgeschermd pakket, dat op elke machine hetzelfde draait. Docker is de bekendste software om dat te doen.

Wat een container is

Een container schermt een programma af van de rest van de machine, net zoals een virtuele machine dat doet, maar met dit verschil: alle containers op een machine delen hetzelfde besturingssysteem. Dat besturingssysteem wordt dus niet telkens mee gevirtualiseerd, waardoor de overhead wegvalt en er ook geen extra licentie bij komt. Een container start in seconden en draait aan bijna de snelheid van de machine zelf.

Wat een container niet kan, is een ander besturingssysteem draaien dan dat van de machine waarop hij staat. Een Linux-container draait dus niet op een Windows-machine zonder dat er ergens een Linux onder zit, en daarvoor heb je een virtuele machine nodig.

Een image en een container

Dat zijn twee verschillende dingen, en het verschil telt zodra je met de commando's begint.

  • Een image is het bevroren pakket: het programma en alles eromheen, klaar om te starten. Je haalt het binnen of je maakt het, en het verandert daarna niet meer.
  • Een container is een image die draait. Van dezelfde image kan je er tien tegelijk starten, en elk daarvan is zijn eigen container met zijn eigen naam.

Op hub.docker.com, Docker Hub, staan de images die anderen gepubliceerd hebben, van webservers tot databanken. Op de bladzijde van elke image staat het commando om ze binnen te halen en een handleiding die zegt hoe ze verwacht gebruikt te worden.

De vier commando's

Van Docker Hub tot een draaiende container
Commando Wat het doet
docker pull Haalt een image van Docker Hub naar je machine
docker build Maakt van een Dockerfile een nieuwe image op je machine
docker run Start een container uit een image
docker ps Toont welke containers er op dit moment draaien

Elk van die commando's praat met de dienst van Docker die op de achtergrond draait, en daar mag een gewone gebruiker niet aan. Je zet er dus sudo voor, anders krijg je een melding dat de toegang geweigerd is.

De Dockerfile

Wil je je eigen programma of je eigen bestanden in een image, dan schrijf je een Dockerfile: een tekstbestand met de stappen die van een bestaande image de jouwe maken. Zo ziet er een uit die de webserver Apache neemt en er je eigen bladzijden in kopieert.

FROM httpd:2.4
COPY ./public-html/ /usr/local/apache2/htdocs/

FROM zegt op welke image je verder bouwt, en 2.4 erachter is de versie. COPY neemt een map van je eigen machine en zet ze op een plaats binnen de image; welke plaats dat is, staat in de handleiding van die image en verschilt per programma.

Poorten doorgeven

Een container is afgeschermd, en dat geldt ook voor het netwerk: een webserver die erin draait, is van buitenaf niet te bereiken tenzij je zegt dat hij dat mag. Dat doe je met de optie -p, die een poort van je machine koppelt aan een poort in de container.

elm@elm-VirtualBox:~$ sudo docker run -dit --name my-running-app -p 8080:80 my-apache2

In 8080:80 staat links de poort van je machine en rechts die van de container. Apache luistert binnenin op 80, en wie op je machine naar localhost:8080 surft, komt daar dus uit. De optie -d laat de container op de achtergrond draaien en --name geeft hem een naam waarmee je hem later terugvindt.
