Schijfruimte bekijken en bestanden zoeken

Twee commando's die de hele schijf overlopen, en die je daardoor allebei tegen dezelfde grens brengen: er staan mappen op de machine waar je als gewone gebruiker niet in mag kijken.

De grootte van een map

Met du, van disk usage, vraag je op hoeveel schijfruimte een map inneemt. Je gebruikt het met twee opties: -s, ofwel --summarize, geeft één totaal in plaats van een regel per submap, en -h schrijft dat totaal in K, M of G.

  1. Vraag op hoeveel er op de hele schijf in gebruik is. Dat duurt even, want elk bestand op de machine wordt bekeken en opgeteld.

    elm@elm-VirtualBox:~$ du -sh / 
    du: cannot read directory '/run/cups/certs': Permission denied
du: cannot read directory '/run/sudo': Permission denied
du: cannot read directory '/etc/ssl/private': Permission denied
du: cannot read directory '/root': Permission denied
du: cannot read directory '/sys/kernel/debug': Permission denied
...
8,5G	/

Het getal onderaan staat er wel, en de regels erboven zeggen waarom het te laag is. Je vraagt als gewone gebruiker de grootte op van mappen waar je geen leesrecht op hebt, en die worden overgeslagen en niet meegeteld. Wat dat leesrecht is, staat bij Gebruikers en rechten.

  1. Vraag nu de grootte van je eigen map op. Daar heb je wel alle rechten, dus die uitvoer is één regel.

    elm@elm-VirtualBox:~$ du -sh /home/elm

Hetzelfde commando met sudo

Met sudo ervoor, van super user do, draait het commando erachter als de root gebruiker, en die mag overal in kijken.

  1. Voer du opnieuw uit, nu met verhoogde rechten. Je vult je eigen wachtwoord in.

    elm@elm-VirtualBox:~$ sudo du -sh / 
    [sudo] password for elm:
Er beweegt niets terwijl je je wachtwoord typt

Geen sterretjes en geen cursor die opschuift. Dat is met opzet zo gemaakt, want dan leest iemand die naast je zit ook de lengte van je wachtwoord niet mee. Typ door en druk op ENTER.

  1. Vergelijk de uitvoer met die van daarnet.

    elm@elm-VirtualBox:~$ sudo du -sh / 
    du: cannot access '/proc/25485/task/25485/fd/4': No such file or directory
du: cannot access '/proc/25485/fd/3': No such file or directory
du: cannot access '/run/user/1000/gvfs': Permission denied
8,6G	/

    Het totaal is hoger dan daarnet, want nu tellen de mappen mee die eerst overgeslagen werden. De meldingen die overblijven zijn van een andere soort: de mappen onder /proc horen bij processen die tijdens het tellen gestopt zijn, en /run/user/1000/gvfs is een koppeling die de grafische omgeving van de gebruiker zelf beheert, en daar komt zelfs root niet in.

Bestanden zoeken

Met find zoek je bestanden vanaf een startmap en in alles wat eronder hangt. Je zet er drie dingen achter: waar je begint, waarop je zoekt en waarnaar.

De drie startpunten die je in dit labo gebruikt
Commando Waar het zoekt
find ~ -name todo.txt Vanaf je eigen map
find . -name todo.txt Vanaf de map waar je nu staat
find / -name todo.txt Vanaf de root, dus over de hele machine

Het tweede woord zegt waarop je zoekt. -name zoekt op de bestandsnaam, en er bestaan er meer: -amin zoekt bijvoorbeeld op wanneer een bestand voor het laatst gelezen is.

  1. Zoek todo.txt vanaf je eigen map, en daarna vanaf de map waar je staat.

    elm@elm-VirtualBox:~$ find ~ -name todo.txt
    elm@elm-VirtualBox:~$ find . -name todo.txt

  2. Zoek nu vanaf de root. Je krijgt dezelfde soort meldingen als bij du, en om dezelfde reden.

    elm@elm-VirtualBox:~$ find / -name todo.txt 
    find: '/proc/5764/ns': Permission denied
find: '/proc/5771/task/5771/fd': Permission denied
find: '/proc/5771/map_files': Permission denied
find: '/proc/5795/fd': Permission denied
...

  3. Zet er sudo voor en vergelijk.

    elm@elm-VirtualBox:~$ sudo find / -name todo.txt 
    /home/elm/automatisering/todo.txt
/home/elm/Desktop/todo.txt
/home/elm/Desktop/3auto/todo.txt
find: '/run/user/1000/doc': Permission denied
find: '/run/user/1000/gvfs': Permission denied

    Nu staan de treffers er wel tussen. Er blijven twee meldingen over, dezelfde koppelingen van de grafische omgeving als daarnet.

De drie paden die je terugkrijgt zijn precies de plaatsen waar je todo.txt gezet hebt: de oorspronkelijke op je bureaublad, de kopie in automatisering, en de kopie die met 3auto naar je bureaublad meeverhuisd is.
